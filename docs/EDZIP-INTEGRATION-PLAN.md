# EDZIP 수합 자료 통합·보완 계획

작성일: 2026-07-24  
상태: **통합 완료 — 아래 70개·16개 표기는 통합 착수 당시 기준이며, 현재 결과는 공개 80개·심층 보강 16개·출처 47건이다.**  
현재 인수인계: [`CODEX-HANDOFF.md`](CODEX-HANDOFF.md)  
대상: 통합 착수 당시 정적 카탈로그(`data/tools.json`, 70개)와 EDZIP 조사 파일(`edzip-ai-tools-pilot`, 16개)을 하나의 운영 가능한 도구 안내 사이트로 정리한다.

## 1. 결론

현재 사이트는 **넓은 도구 목록을 빠르게 검색하는 MVP**이고, EDZIP 자료는 **학교 도입 조건을 판단하고 비교하기 위한 심층 조사 원장**이다. 따라서 EDZIP JSON을 현재 `tools.json`에 그대로 덮어쓰지 않는다.

권장 방식은 다음과 같다.

1. 현재 70개 목록과 UI는 유지한다.
2. EDZIP의 검증된 상세 정보를 공통 확장 필드로 흡수한다.
3. 이미 있는 도구 6개를 먼저 보강하고, 신규 후보 10개는 검증 상태를 표시한 뒤 단계적으로 공개한다.
4. 출처·언어·S2B·검토 판정은 목록 카드의 단순 태그가 아니라 별도 구조로 보존한다.

이 방식은 기존 검색·필터와 링크를 깨지 않으면서, “도구가 많은 사이트”를 “수업·도입 결정을 도와주는 사이트”로 발전시킨다.

### 도구 중복·추가 판정

- 이름이 정확히 같은 기존 도구: ChatGPT, NotebookLM, Kahoot! (3개)
- 표기만 다른 기존 도구: Gemini/Gemini for Education, Canva/Canva Education, MagicSchool AI/MagicSchool (3개)
- 신규 검토 대상: Claude, Microsoft 365 Copilot for Education, Adobe Express for Education, Diffit, Curipod, Wayground(구 Quizizz), Khanmigo, ElevenLabs, Brisk Teaching, SchoolAI (10개)
- 후속 조사 대기열 7개는 정식 목록에 즉시 넣지 않고 `조사 중`으로 분리한다. 이 중 매쓰홀릭T는 기존 `매쓰홀릭T`와 동일성부터 확인한다.

### 발견한 정리 필요 사항 — 해결 완료

- 통합 착수 당시 `README.md`는 70개를, `docs/STATUS.md`의 카테고리 합계는 64개를 표기했다. 현재는 실제 공개 데이터 80개로 정정했다.
- EDZIP의 “홈 공개목록에서 미확인”은 S2B 미입점이 아니다. UI와 데이터에서 `미입점`이라는 표현을 사용하지 않는다.
- EDZIP의 `Gemini for Education`, `Canva Education`, `Adobe Express for Education`은 일반 서비스와 교육기관용 상품 조건이 다르므로, 단순 별칭 처리 전에 교육용 플랜을 별도 `edition`으로 기록한다.

## 4. 단계별 실행 계획

### 0단계 — 기준 고정 및 백업 (반나절)

- `docs/SCHEMA.md`에 확장 필드와 상태값(`공개`, `조건부 공개`, `조사 중`, `공개 보류`)을 추가한다.
- 현행 70개를 기준 데이터로 고정하고, ID·URL·카테고리·연령제한의 검증 스크립트를 만든다.
- README/STATUS의 도구 수와 카테고리 합계를 실제 JSON 기준으로 정정한다.
- `Wayground (구 Quizizz)`처럼 변경된 이름을 `aliases`로 보관해 이전 명칭도 검색되게 한다.

완료 기준: 스키마 문서, 상태 정의, 데이터 검사 명령이 있고 기존 70개가 무오류로 통과한다.

### 1단계 — 기존 6개 심층 보강 (1일)

대상: ChatGPT, Gemini, NotebookLM, Canva, MagicSchool AI, Kahoot!.

- EDZIP 원장의 언어·도입·안전·판정·출처·S2B 정보를 해당 기존 ID에 병합한다.
- 교육용 플랜은 일반 서비스와 구별해 `edition`에 작성한다.
- 기존의 `korean_support`, `pricing`, `age_limit`은 호환성 유지용 요약값으로 남기고, 상세값과 충돌하면 공식 출처를 재확인한다.
- 각 도구의 상세 화면에 “학교 적용 판정”, “교사 검토 지점”, “최종 확인일”을 우선 노출한다.

완료 기준: 6개 모두 E2 이상 근거, 최소 연령/학생 계정/개인정보 주의, 언어 세부 정보, 공식 출처가 표시된다.

### 2단계 — 신규 10개 도입 심사 및 공개 (2~3일)

우선순위는 수업 활용 폭과 기존 카테고리의 빈 곳을 기준으로 한다.

1. Wayground, Diffit, Curipod — 평가·수업자료 영역 보강
2. Claude, Microsoft 365 Copilot for Education, Brisk Teaching, SchoolAI — 교사 업무·AI 활용 영역 보강
3. Adobe Express for Education, ElevenLabs, Khanmigo — 디자인·음성·튜터링 영역 보강

각 도구는 다음 게이트를 통과할 때만 공개한다.

- 공식 주소와 운영 상태
- 학생 직접 사용 시 최소 연령·계정 흐름
- 무료 범위 및 학교·교육기관 요금의 구분
- 개인정보·파일 업로드·생성 결과의 주의점
- 한국어 공식 지원과 현장 검증 필요 여부
- 최소 1개 이상의 공식 출처, 판정 사유, 확인일

미확인 항목이 있으면 `조사 중` 또는 `조건부 공개`로만 노출하며 추천 목록에서는 제외한다.

### 3단계 — 탐색·상세·비교 UI 보완 (1~2일)

- 필터 추가: 교과, 수업 단계, 이용자, 학교 적용 판정, 학생 계정, 음성/번역, S2B 공개목록 확인.
- 상세 모달 추가: 대표/보조 분야, 언어 4영역, 도입 조건, 안전 주의, 근거 수준·출처, S2B 상품 정보.
- 최대 4개 비교 기능 추가: 한국어 상태, 학생 계정, 무료 시작, 최소 연령, 안전 주의, 판정, S2B를 고정 비교 행으로 제공.
- 확인일이 180일을 넘은 도구는 “재검토 필요” 배지를 표시한다.

완료 기준: 모바일 360px부터 데스크톱까지 카드·상세·비교가 작동하고, 키보드만으로 필터·비교·모달을 조작할 수 있다.

### 4단계 — 운영 체계화 (반나절)

- `data/tools.json`과 `data/sources.json`의 ID 무결성, 중복, 필수 근거, 오래된 확인일, URL 형식을 자동 검사한다.
- 정기 검토 주기를 정한다: 연령·가격·약관은 90일, 기능·언어는 180일, S2B 공개목록은 180일.
- 후속 후보 7개는 정식 목록과 분리된 `researchQueue`로 관리하고, 검증 완료 시에만 승격한다.

## 6. 이번 통합에서 제외할 것

- EDZIP 내부 조회수·저장수·활용사례수에 근거하지 않은 인기 순위
- S2B 홈 공개목록만으로 한 “미입점” 판정
- 아직 근거가 부족한 후속 후보의 정식 추천
- 사용자 로그인, 댓글, 구매 기능

## 8. 후속 확장 — AI 에듀테크 추천 도우미

### 목적

교사가 자연어로 수업 맥락을 입력하면, 현재 큐레이션 데이터 안에서 조건에 맞는 도구 2~3개를 짧은 이유와 함께 제안한다. 이 기능은 공개 웹을 임의로 검색하는 챗봇이 아니라, 검증된 도구·출처·학교 적용 조건을 우선하는 **추천 인터페이스**로 설계한다.

### 대화 흐름

1. 교사가 학년, 교과, 수업 목표, 학생 직접 사용 여부를 한 문장으로 입력한다.
2. 필요한 정보가 부족하면 도우미는 한 번에 한두 가지만 되묻는다. 예: “학생 계정 사용이 가능한가요?”, “한국어 음성 기능이 필요한가요?”
3. 먼저 택소노미와 심층 보강 데이터를 규칙으로 좁힌 뒤, AI는 후보별 활용 이유·주의점·다음 행동만 설명한다.
4. 각 제안에는 연령·계정·요금·한국어·S2B·확인일을 함께 표시하고, 상세 카드와 공식 출처로 연결한다.

### 추천 규칙

- 학생 직접 사용 조건이 불명확하거나 `조건부 공개`인 도구는 기본 추천에서 제외하고, 교사 준비용 대안이 없을 때만 주의 문구와 함께 제시한다.
- `verified_at`이 180일을 넘긴 도구는 추천 이유보다 `재검증 필요` 안내를 먼저 표시한다.
- 결과는 최대 3개로 제한한다. 추천하지 않은 후보와 순위 점수는 노출하지 않는다.
- 교사의 수업 맥락을 일반화한 뒤 서버로 보내며, 학생 이름·성적·상담 내용·개인정보 입력을 금지한다.

### 단계별 구현

| 단계 | 범위 | 완료 기준 |

### 기술 경계

- 정적 카탈로그와 추천 로직은 분리한다. 원본 도구 데이터는 클라이언트에서 읽되, AI 호출 키와 대화 처리는 서버 측(예: Cloudflare Worker)에서만 수행한다.
- 모델에는 사용자가 요청한 조건과 후보 도구의 필요한 필드만 전달한다. 전체 출처 레지스트리와 학생 개인정보를 전달하지 않는다.
- AI가 새 도구를 발명하거나 현재 데이터에 없는 가격·연령 조건을 단정하지 않도록, 응답 형식을 후보 ID·추천 사유·주의점으로 제한하고 화면에서 ID를 검증한다.
